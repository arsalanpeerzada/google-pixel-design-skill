# Chips: Assist, Filter, Input & Suggestion Guidelines

> Component reference for Google Pixel & Material 3 Expressive.

Chips allow users to enter information, make selections, filter content, or trigger contextual actions in a compact visual footprint.

---

## 1. The 4 Chip Types

| Type | Intended Role | Visual Anatomy |
| --- | --- | --- |
| **Assist Chip** | Triggers a contextual smart action | Leading icon + text label (e.g. "Add to calendar") |
| **Filter Chip** | Toggles a filter state on/off | When active, displays a leading checkmark in `secondaryContainer` |
| **Input Chip** | Represents user-created data | Entity avatar/icon + label + trailing "X" delete button |
| **Suggestion Chip**| Suggests potential queries or actions | Plain label or spark icon; dynamically generated by AI/system |

---

## 2. Dimensions & Shape

- **Height:** Standard chip height is **$32\,\text{dp}$** (compact variant $28\,\text{dp}$).
- **Touch Target:** The interactive bounding box must expand to **$48 \times 48\,\text{dp}$** via transparent touch padding.
- **Corner Radius:**
  - Classic M3: $8\,\text{dp}$ rounded corners.
  - M3 Expressive: Full pill rounding ($9999\,\text{dp}$ / Stadium) for a softer, organic aesthetic.
- **Horizontal Padding:** $16\,\text{dp}$ standard padding, or $8\,\text{dp}$ leading padding when an icon is present.

---

## 3. Color Tokens

- **Unselected / Inactive:** Transparent background with $1\,\text{dp}$ `outlineVariant` border, or subtle `surfaceContainerLow` fill.
- **Selected Filter Chip:** Solid `secondaryContainer` background with `onSecondaryContainer` text/icon, dropping the outline border.

---

## 4. Audit Checklist

- [ ] Does the chip touch target meet the $48 \times 48\,\text{dp}$ accessibility minimum despite its $32\,\text{dp}$ visual height?
- [ ] Are filter chips clearly distinct when selected (background fill changes to `secondaryContainer`)?
- [ ] Are trailing delete buttons on input chips easily tappable without accidentally triggering the main chip?
